Check your hardware before flashing

This build targets LilyGO T-Deck / T-Deck Plus, ESP32-S3, SX1262, 16 MB flash and 8 MB OPI PSRAM, configured for 433 MHz. It is not a T-Deck Pro/Max, Meshtastic or universal 868/915 MHz image. Use a matching radio and antenna, and permitted radio settings.

Fresh installation erases all device flash, including saved settings and Bluetooth pairings. Back up first. Do not use the merged image as a data-preserving update.

01 / Fresh installation

  1. Back up the existing firmware and data. Connect a USB data cable and turn the board on.
  2. Open the Q-P1NG website in a desktop browser with Web Serial support, such as Chrome or Edge, over HTTPS.
  3. Close any serial monitor using the device. Choose the firmware installer and select the T-Deck serial port.
  4. If the bootloader does not connect, hold the trackball centre, press RESET, then release the trackball.
  5. Confirm the fresh installation in the installer. Keep the cable connected until writing and verification finish.
  6. Press RESET if the display remains in download mode. The screen and QP1NG_USB_HELLO should report version 15.8.
  7. Pair the phone again if needed. The PIN is in Setup → Phone pairing PIN.

The manifest uses one merged image at offset 0x0. It includes the bootloader, partition table, OTA selection and application. No filesystem image or external graphics pack is needed.

03 / Radio modes

Mesh keeps the existing phone bridge and relay policy, and can carry standalone room messages.

Direct disables local relays and gives outgoing packets a zero hop budget.

Listen receives only. No messages, relays or room receipts are transmitted.

The shared profile stays at 433 MHz, SF9, BW250, CR4:5, sync 0x14. Setup power applies to standalone messages; the phone retains its own requested power. Settings reset on reboot.

04 / Chat without a phone

  1. On one T-Deck select Setup → Create room. A fresh random room code appears.
  2. Share it privately. On the other T-Deck select Setup → Join room and enter all 32 hexadecimal characters.
  3. Press Enter on both devices to activate the room. The code is then removed from the screen.
  4. Open Chat, type a message, review it and confirm. Messages support up to 172 printable ASCII characters and fit a single radio fragment.
  5. “Received by a room member” means at least one member returned an authenticated receipt. “Delivery unknown” is not proof that the message was lost.

There are at most three transmission attempts and a 60-second overall deadline. Six recent messages remain in RAM. This room is separate from the phone’s contact list and chat identities.

05 / Privacy and session limits

Room codes, drafts and recent messages stay in RAM. Restarting or confirming Clear room & messages removes the local room session. Bluetooth bonds remain in device storage.

The random room code is 128-bit key material, not a human password. AES-256-GCM authenticates possession of the shared room secret; members can impersonate each other. This protocol does not provide forward secrecy or verified individual identities.

Replay tracking covers 32 sender sessions and resets when the room is cleared or the device restarts. Use a new random code for each session. Reusing an old code after restarting can allow old packets to be replayed. RAM-only storage does not make a device forensically empty or untraceable.

06 / Recovery and diagnostics

If the screen stays dark after installation, press RESET and check the exact board variant. If a serial port is busy, close Arduino Serial Monitor and the website’s live monitor before retrying. If the keyboard is absent, restart the board and inspect its hardware connection.

Read-only commands: QP1NG_USB_HELLO, QP1NG_USB_PING, QP1NG_USB_DIAG. Diagnostics expose state, input counts and memory totals; they do not expose room codes, pairing PINs or message content. Production firmware excludes test input and screenshot commands.
